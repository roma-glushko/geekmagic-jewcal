# JewCal: context for Claude Code

Pixel-art Jewish calendar firmware for two GeekMagic SmallTV models (ST7789 240×240 on both). Calendar data comes from
the Hebcal.com REST API and weather from Open-Meteo. The device interprets both and draws them.
- **SmallTV Pro:** ESP32-D0WD, 520 KB SRAM, **no PSRAM**. Firmware in `firmware/`.
- **SmallTV Ultra:** ESP8266, ~80 KB DRAM, no USB data, WiFi OTA only. Firmware in `ultra/`. The user's own device
  is an Ultra.

## Layout and commands

Three cargo "worlds":
- **The repo root** is a host workspace (`model`, `ui`, `app`, `sim`) on the default stable toolchain.
- **`firmware/`** (Pro) is excluded from that workspace. It has its own `[workspace]`, `rust-toolchain.toml` (`esp`)
  and `.cargo/config.toml` (target `xtensa-esp32-espidf`, build-std, ESP-IDF v5.2.3). It pulls in `model`, `ui` and
  `app` as path dependencies.
- **`ultra/core/`** (Ultra) is also excluded, with its own workspace: a `staticlib` for `xtensa-esp8266-none-elf`
  (`esp` toolchain, build-std core+alloc). `ultra/` itself is a PlatformIO project (Arduino ESP8266 core 3.1.2,
  `espressif8266@4.2.1`). Its `scripts/rust_core.py` builds the core and links it in.

```bash
make zip                                     # Pro: build + dist/jewcal-pro-<ver>-<commit>.zip (full image @0x0, app @0x10000, elf)
make flash PORT=/dev/cu.usbserial-XXXX       # build + flash + monitor (FEATURES=backlight-gpio21 for the other board)
make check                                   # everything CI runs on the host (fmt, clippy -D warnings, tests, no_std)
cargo test                                   # host tests (model + ui)
cargo clippy --all-targets                   # keep clean (CI denies warnings)
cargo run -p jewcal-sim -- gallery --out shots   # render every screen -> shots/index.html (view PNGs to review art)
cargo run -p jewcal-sim -- agenda nyc 2027-04-21T12:00
cd firmware && bash -c 'source ~/export-esp.sh && cargo build --release'   # device build
make flash                                   # build + flash + monitor (first time: backs up the device)
make ultra                                   # SmallTV Ultra: installer + firmware (PlatformIO in ~/.platformio/penv)
make ultra-zip                               # -> dist/jewcal-ultra-<ver>-<commit>.zip
make ultra-ota HOST=jewcal.local             # upload to an Ultra already running JewCal
make ultra-check                             # CI's Ultra guards: sizes, ROM helpers, static RAM, 3 KB stack budget
make firmware-check                          # clippy on the Pro firmware (CI denies warnings)
cargo test -p jewcal-ui --features packed    # the UI with the Ultra's 4-bit canvas (part of `make test`)
cargo run -p jewcal-sim -- gen-cfont         # regenerate ultra/src/font_body.h after changing the BODY font
make docs / make docs-serve                  # the user guide (docs/, mkdocs.yml; Read the Docs builds .readthedocs.yaml)
make docs-assets                             # regenerate docs/assets (logo, pixel font, animated SmallTV) and docs/images (pages, headless Chrome)
```

The esp toolchain env is not inherited by tool shells: always `source ~/export-esp.sh` in the same `bash -c`.
`cargo test` does not rebuild the `jewcal-sim` binary. Run `cargo build -p jewcal-sim` before re-rendering.

## Module map

| Path | Responsibility |
|---|---|
| `model/src/json.rs` | Streaming JSON splitter: chunks in, the raw text of selected values out (`no_std`) |
| `model/src/wire.rs` | `EventsParser`/`ZmanimParser` (fed in chunks, on the splitter) and `std::io::Read` front ends, plus `/complete` |
| `model/src/classify.rs` | Hebcal item → `Kind`. Uses `title_orig` and normalizes curly quotes. Curates the modern and minor days kept |
| `model/src/calendar.rs` | `CalendarModel`: **periods** (runs of Shabbat/YT days, built from the day structure), fasts, agenda spans |
| `model/src/snapshot.rs` | `Snapshot::at(model, tz, now)`: state (in period / in fast / normal), holiday views (`HolidayView`: window, period, related fast, day strip), Omer, and every view the screens use |
| `model/src/weather.rs` | Open-Meteo URL and parse. Numbers are captured as `RawValue` text and converted to fixed-point tenths; also units and WMO code → `Condition` |
| `model/src/hebrew.rs` | Hebrew calendar arithmetic (integer only) |
| `model/src/tz.rs`, `tz_table.rs` | POSIX TZ evaluator; IANA name → POSIX string table (generated by `sim gen-tz`) |
| `model/src/hebcal.rs` | URL builders and the fetch `Window` |
| `ui/src/canvas.rs` | 120×120 indexed canvas, primitives, text, `diff`, `dissolve` |
| `ui/src/fonts.rs`, `sprites.rs` | ASCII-art fonts (TINY 3×5, BODY 5×7, NUM 4×7 digits) and sprites, decoded by `const fn` |
| `ui/src/screens/*` | Main (with the season ribbon), period, upcoming, month, `holidays.rs` (Rosh Hashana, Yom Kippur, Sukkot, Pesach, Shavuot, Purim, Tisha B'Av), `seasons.rs` (Omer, Elul), `festival.rs` (Chanukah), `weather.rs`, info/setup/message |
| `ui/src/scheduler.rs` | Main screen by default; secondary screens every `cycle_min`, `dwell_s` each |
| `ui/src/text.rs` | Hebcal title → display text, abbreviation ladder (`fit`), wrapping, countdowns |
| `sim/src/*` | Fixture recorder, gallery and PNG renderer, tz table generator; `docs.rs`, `webfont.rs`, `hero.rs` make the user guide's assets |
| `docs/` | The user guide. `stylesheets/extra.css` is the device's look: Sweetie-16, monospace text, headings in the generated BODY web font (8 px to the em: use 16/24/32 px so pixels stay whole) |
| `firmware/src/main.rs` | Boot sequence, render loop (`Ui`, `Panel`), fetch thread, setup mode |
| `firmware/src/display.rs` | ST7789 driver, 2× indexed flush with DMA |
| `firmware/src/httpc.rs` | One-shot HTTPS with a streamed, capped body; a global lock allows one TLS session at a time |
| `firmware/src/web.rs` | Settings page (also at `http://jewcal.local/` via mDNS), `/cities` proxy, `/screen.bmp`, AP setup page |
| `firmware/src/settings.rs` | NVS persistence (namespace `jewcal`) |
| `app/src/settings.rs` | `Settings` (shared): Hebcal query, fetch key, units, brightness; `to_text`/`from_text` for the Ultra's EEPROM |
| `app/src/web.rs` | The settings and setup pages (written to any `fmt::Write`), form application, URL/HTML helpers, BMP header |
| `app/src/device.rs` | The Ultra's single-threaded loop: `next_request` → `feed` → `finish`, `frame`; tested with fixtures in `app/tests/device.rs` |
| `ultra/core/src/lib.rs` | The Ultra's Rust core: allocator over umm_malloc, panic → `jc_panic`, the `jc_*` C ABI (`ultra/src/jewcal_core.h`) |
| `ultra/src/main.cpp` | Ultra boot and loop: normal / setup (AP + captive portal) / safe mode, 5 fps frames, one HTTP request at a time |
| `ultra/src/display.cpp`, `flush.cpp` | ST7789 on HSPI mode 3; C text for the installer and safe mode; row-hash diff flush of the canvas |
| `ultra/src/net.cpp`, `web.cpp` | Plain-HTTP streaming GET, WiFi join/AP; ESP8266WebServer routes, `/update` (OTA) |
| `ultra/src/crash.cpp`, `store.cpp` | Crash counter in RTC memory (safe mode after 3); settings text in EEPROM |
| `ultra/src/loader/installer.cpp` | The installer: small enough for the stock updater, receives the full image |

CI (`.github/workflows/ci.yml`) runs exactly these targets:
- the host job runs `make check` and the gallery;
- the Ultra job runs `make ultra-check` and `ultra-zip`;
- the Pro job runs `make firmware-check` and `zip`;
- a `v*` tag publishes a release with both zips.

Keep the Makefile targets and the workflow in step. Our C++ is built with `-Wall -Wextra -Werror`.

## Gotchas

- **No floats through serde_json on Xtensa.** Deserializing `f32`/`f64` fails to codegen ("Cannot select
  XtensaISD::PCREL_WRAPPER"). Hebcal's only floats are `location.latitude/longitude`; leave them out of the structs.
  Avoid `serde_json::Value`, `#[serde(flatten)]` and `#[serde(untagged)]` in code that runs on the device. Coordinates
  entered by the user stay strings and are validated as text.
- **No 14 KB arrays on the stack.** `Box::new([0; N])` may build the array on the stack first. Use
  `vec![..].into_boxed_slice().try_into()` (see `Canvas::new`, `Display::band`). The same applies to cloning in
  HTTP handlers (`px.to_vec()`).
- **Hebcal data quirks:**
  - Titles use curly quotes (`Tish’a B’Av`, `CH’’M`) unless `title_orig` is present. `classify::normalize` fixes them.
  - At high latitudes in summer there is no havdalah or nightfall item. Never pair candles with havdalah to find
    periods; periods come from the day structure, and every time is `Option`.
  - Nightfall can come after midnight (Helsinki, May), in which case the item is dated the next day. See
    `calendar::evening_time`.
  - Ta'anit Bechorot and Friday fasts have no "Fast ends" item. The 9 Av "Fast begins" memo is `Erev Tish'a B'Av`.
  - Israeli locations force the Israel schedule. Do not send `b=18` unless the user chose it: Hebcal's default
    already applies Jerusalem's 40 minutes.
- **Changing `[package.metadata.esp-idf-sys]`** (e.g. the `espressif/mdns` remote component) does not re-run
  esp-idf-sys's build script. Run `cargo clean -p esp-idf-sys --release` in `firmware/` first. Otherwise the
  `esp_idf_comp_*` cfgs stay off and `esp_idf_svc::mdns` "does not exist".
- **GPIO3** is both SPI CS and UART0 RX, so there is no serial input after display init.
- **Backlight pin:** GPIO25 inverted on the common board; feature `backlight-gpio21` for the other variant.
- **Holiday screens follow the Hebrew day.** It rolls over at sunset (`snapshot.hebrew.civil`), so on Erev Pesach
  after sunset the Pesach screen says "DAY 1". Sunsets come from the `/zmanim` request. Tests that need the
  rollover must load a `zmanim-*` fixture (see `model_with_sun` in `model/tests/fixtures.rs`).
- **Weather numbers are floats.** Never deserialize them as `f32`/`f64` (see the serde gotcha above). `weather.rs`
  takes `Box<RawValue>` and converts it to tenths with `tenths()`. Hebcal's `location.latitude/longitude` are read
  as raw text too (`wire::raw_text`) and passed unchanged into the Open-Meteo URL.
- **Text must fit.** `ui/tests/render.rs` checks every real Hebcal title against the slot widths. When it fails, add
  a rung to `text::ABBREV` instead of shrinking fonts.

- **`model`, `ui` and `app` are `no_std` + `alloc`** (the Ultra). Import `crate::prelude::*` for
  `Vec`/`String`/`format!`; use `core::`/`alloc::` paths. Only the `std` feature (on by default) may use `std`
  (`std::io::Read` front ends). Check with `cargo build -p jewcal-app --no-default-features`.
- **Ultra memory:** ~49 KB of heap at boot, ~40 KB with WiFi up.
  - The packed canvas takes 7.2 KB and the model ~15 KB.
  - A refresh keeps the old model until the new events and sun times have arrived, then drops it before
    `CalendarModel::build`.
  - `app/tests/memory.rs` measures one refresh on the host (64-bit, so it overstates).
- **Ultra stack: 4 KB, and it must stay so.** The core carves the loop stack out of the SDK's system stack; anything
  larger pushes that stack below 0x3FFFE000 into ROM data.
  - Big buffers are `static`; each kind of response is finished in its own `#[inline(never)]` function; the parsers
    are boxed and finished in place (`take()`).
  - Check with `make ultra-stack` (deepest static path ~2.6 KB from `loop()`, plus ~0.8 KB of lwIP behind the page
    sink and the interrupt frames). The settings page shows `ESP.getFreeContStack()`.
- **Ultra linking:** `scripts/rust_core.py` moves the core's code and constants into flash.
  - The archive members are renamed to `*.c.o`, so the Arduino linker script maps their code to flash.
  - `.rodata*` is renamed to `.irom0.pstr*`.
  - Byte reads from flash work only with `-D NON32XFER_HANDLER`; never call Rust from an ISR.
  - compiler_builtins is left out of the archive. Its weak `__udivsi3`/`__umodsi3`/`memcpy`/... would replace the
    ROM's for the whole firmware, and IRAM interrupt handlers would then run flash code during flash writes.
    Check `nm firmware.elf | grep __udivsi3` → `A 0x4000e21c`.
- **Ultra network:** plain HTTP (`device::plain_http`): there is no room for TLS. Hebcal's `/complete` redirects
  to HTTPS, so the Ultra's city search proxies Open-Meteo's geocoder; `web::SEARCH_JS` reads both answers.
  - The installer must stay well under the stock updater's ~500 KB slot (it is ~325 KB).
  - `/update-<token>` and `/forget` need a per-boot token that only the settings page shows (`web.cpp`).
- **Ultra crash accounting:** RTC user memory blocks 0–31 belong to the OTA bootloader; `crash.cpp` uses block 32
  onwards. `custom_crash_callback` (IRAM, direct RTC writes) marks every crash path. abort() and friends restart as
  a soft reset, which would otherwise look deliberate.
- **Ultra display init order:** configure SPI (mode 3) *before* releasing the panel's reset.
  - The panel's CS is tied low, so it counts every rising clock edge.
  - After a power-up the clock-polarity bit starts at 0, so switching to mode 3 raises the clock: a stray bit.
  - A warm restart keeps the bit, so OTA restarts hide the bug; cold boots stayed black until this was fixed
    (2026-10-11).
- **Ultra hardware status (2026-10-11, the user's unit):** working.
  - The two-step OTA install worked.
  - Calendar screens, the settings page and OTA updates all work.
  - Cold boots work since the display init-order fix.
  - Still worth watching: the Device line (free heap, largest block, stack low-water mark) after a nightly
    refresh.

## Fixtures

`model/tests/fixtures/` holds real responses:
- `events-<city>-<year>.json` for a full civil year;
- `zmanim-<city>-<date>.json`, trimmed to sunrise/sunset;
- `weather-<city>.json`, one Open-Meteo snapshot per unit system.

`sim record` downloads only missing files. Recording is polite: about one request every 400 ms, with a User-Agent.
Tests treat the fixtures as oracles (UTC offsets, `hdate`), so do not hand-edit them.
